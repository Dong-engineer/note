# 前言

基于注解的容器配置，学习到这里可能就会有小白疑问？学习过了 XML 为什么还要学习注解呢？二者区别在哪？谁更好一点？

基于 XML 文件，其实更像开发者在另一文件中描述好 Bean ，然后交给容器去管理，这也是 Spring 实现控制反转的原理，于此同时 Spring 将容器与容器隔离，Bean 与 Bean 之间隔离，每个都有着清晰的各自的生命周期。

基于注解，和 XML 差不多，但是注解主要应用字节码数据注入，来完成控制反转的实现。基于注解需要在源码中声明，这就形成了对源代码的侵入。

两个方法有各自的优缺点，并不能说谁好谁坏，因为存在即合理。

具体的使用情况由开发者定，两者也可混合使用。

如果两者开发者混合使用了，**那么开发者需要知道：注解注入是在XML注入之前进行的。因此，XML配置覆盖了通过这两种方法注入的属性的注解。**

二者在实际开发中应当如何使用，等学完本章，开发者应当自会定夺。
