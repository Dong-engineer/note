# 异常

Java 基础的学习就要结束了，本章节开始异常的学习，异常其实在前面已经有所了解，就是程序发生了错误从而导致程序不能正常运行。

而 Java 将这所发生的错误创建一个对象并将其转移交给运行时系统，该对象被称为异常对象。

该对象包含有关错误的信息，包括错误发生时的错误类型和程序状态。

创建异常对象并将其传递给运行时系统这一行为称为抛出异常。

既然发生了异常，肯定是要去发现其所在之处，然后解决，再次去调试。

## Java 对于异常的做法

### 怎么发现的异常

异常通常是因为开发者没有正确使用 Java 所提供的语法，或者在进行逻辑运算的时候逻辑是错误的，又或者是开发者在对整个系统的业务规划是错误的（从而导致没有正确使用语法）等等。那么Java 是如何发现异常的？

**运行时异常是由 JVM 自动检测并抛出**

**编译时异常由开发者显示在代码中进行处理或者声明抛出**

在 JVM 中所有的方法的调用是一个栈结构。

开发者知道 `main()` 方法是主程序入口，故而 `main()` 方法第一个入栈，被压入栈底，其余方法会按调用顺序依次入栈。

假设运行时发生了异常，最终的栈（Java 成为调用栈）中的结果应该是如下：

`main()`（主方法）→ 带有异常处理器的方法 → 没有异常处理器的方法 → 发生错误的方法

### 如何管理的异常

接下来就是 Java 如何发先异常并管理异常的：

**运行时异常是由 JVM 自动检测并抛出**

**编译时异常由开发者显示在代码中进行处理或者声明抛出**

当 JVM 在运行时发现异常 JVM 会将其抛出置于栈的最顶层，然后搜索从发生错误的方法开始，并按照调用方法的相反顺序通过调用堆栈进行。

即 JVM 会从当前发生错误的方法开始寻找处理错误的方式（try...catch或throws，这后面讲述），如果当前方法没有处理错误的方式则会**向上抛出**，即**向上层栈帧（调用它的方法）传播**，如果上层栈没有处理异常的方式，则会继续向上抛出，知道有带有异常处理器的方法

以下用代码模拟以下：

```java
public class ExceptionFlow {
    public static void main(String[] args) {
        // 1. main() 调用 methodWithHandler()
        methodWithHandler();
    }

    // 对应 “带有异常处理的方法”
    public static void methodWithHandler() {
        try {
            // 2. 这里调用了 methodWithoutHandler()
            methodWithoutHandler();
        } catch (ArithmeticException e) { 
            // 5. 异常被捕获，执行这里的逻辑
            System.out.println("在 methodWithHandler 捕获了异常: " + e.getMessage());
        }
    }

    // 对应 “没有带有异常处理器的方法”
    public static void methodWithoutHandler() {
        // 3. 这里调用了 methodWhereError()
        methodWhereError();
    }

    // 对应 “发生异常的方法”
    public static void methodWhereError() {
        // 4. JVM自动检测，抛出异常（除数为 0）
        int result = 10 / 0; 
    }
}
```
