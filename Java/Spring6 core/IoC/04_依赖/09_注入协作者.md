# 注入协作者（Autowiring Collaborators）

注入协作者，什么是协作者呢？

学习过Servlet的应该都知道什么是协作者，在实际开发时，是要分层控制的，在Servlet中DAO层是用来操作数据库的，service 层是用来控制服务逻辑的，servlet层用来处理接受前端的请求，在层层之间是紧密相连，相互协作的，servlet层通过调用service层来达到返回数据的逻辑，service层通过调用DAO层来达到操作数据库的目的，而层与层之间相互的关系，叫做协作者。

**注意，协作者概念是抽象的，上面作者将他具体化了，便于理解，这是一种思想！**

在后面的Spring6的学习中同样会学到分层控制。

回归正题，注入协助者就是通过Spring的IOC实现对另一层级的bean的调用，来实现系统功能。

这里基于XML文件实现注入协作者，如下：

假设我们已经分别有一个`UserDao、UserService、UserServlet`类。(这里只是方便与理解，在Spring中有Spring的写法，这里用的Servlet)，以下是普通的注入：

```java
public UserDao {
    
    public void insterUser() {
        System.out.println("正在插入一个对象");
    }
    
}
```

```java
public UserService {
    
	private UserDao userDao;
    
    // setter注入
    public void setUserDao(UserDao userDao) {
        this.userDao = userDao;
    }
}
```

```java
public UserServlt {

	private UserService userService;
	
	// setter注入
	public void setUserService(UserService userService) {
	    this.userService = userService;
	}

}
```

```xml
<bean id="userServlet" class="包名.UserServlt">
	<!-- 根据属性名字匹配 -->
    <property name="userService" ref="userService">
</bean>
<bean id="userService" class="包名.UserService">
	<!-- 根据属性名字匹配 -->
    <property name="userDao" ref="userDao">
</bean>
<bean id="userDao" class="包名.UserDao"></bean>
```

没错，在Spring容器初始化时，这三个bean之间存在依赖关系会随之创建并配置。Spring为开发者提供了一种非常简洁，依赖关系一眼明了的方式，就是注入协作者。

想要达成注入协作者的目的，可以使用`autowire`属性，这并不代表注入协作者只有这一种方式，这只是Spring建议我们去这么做，实际视情况而定。

## 自动注入

### 自动注入的实现

使用了`autpwire`属性，准确来说是**自动注入**，或者叫做**自动装配**

如下：

```xml
<bean id="userService" class="包名.UserService" autowire="byName"/>
<bean id="userDao" class="包名.UserDao"/>
```

对于`autowire`属性，Spring提供了以下几种值：

| 模式          | 解释                                                         |
| :------------ | :----------------------------------------------------------- |
| `no`          | （默认）没有自动注入。Bean引用必须由 `ref` 元素来定义。对于大型部署来说，不建议改变默认设置，因为明确指定协作者会带来更大的控制力和清晰度。在某种程度上，它记录了一个系统的结构。 |
| `byName`      | 通过属性名称进行自动注入。Spring寻找一个与需要自动注入的属性同名的Bean。例如，如果一个Bean定义被设置为按名称自动注入，并且它包含一个 `master` 属性（也就是说，它有一个 `setMaster(..)` 方法），Spring会寻找一个名为 `master` 的Bean定义并使用它来设置该属性。 |
| `byType`      | 如果容器中正好有一个 property 类型的 bean 存在，就可以自动注入该属性。如果存在一个以上的bean，就会抛出一个致命的 exception，这表明你不能对该bean使用 `byType` 自动注入。如果没有匹配的 bean，就不会发生任何事情（该属性没有被设置）。 |
| `constructor` | 类似于 `byType`，但适用于构造函数参数。如果容器中没有一个构造函数参数类型的bean，就会产生一个致命的错误。 |

重点是`beName`模式，下面会讲解：

对于正常的setter注入，都知道要保证`ref`引入的另一bean的名字（id、name）和其对应的bean的名字相同即可。

```xml
<bean id="userServlet" class="包名.UserServlt">
	<!-- 根据属性名字匹配 -->
    <property name="userService" ref="userService">
</bean>
<bean id="userService" class="包名.UserService">
	<!-- 根据属性名字匹配 -->
    <property name="userDao" ref="userDao_aaa">
</bean>
<bean id="userDao_aaa" class="包名.UserDao"></bean>
<!-- 以上代码不会报错 -->
```

但是，**对于自动注入来说，Spring规定了：被引入bean的（id、name）名字必须和引入bean中的成员变量、`setter`注入方法名字一致**，如下：

```xml
<bean id="userService" class="包名.UserService" autowire="byName"/>
<bean id="userDao_aa" class="包名.UserDao"/>
<!-- 报错，空指针错误，Spring找不到和UserService的成员变量、setter注入方法名字相同一致的bean -->
```

```java
public UserService {
    
	private UserDao userDao;
	
	// setter注入
    // setter注入方法的名字：set不取，取后面单词的首字母小写，即userDao
	public void setUserDao(UserDao userDao) {
	    this.userDao = userDao;
	}

}
```

为了避免错误 ，和保证阅读理解，直接用idea生成的即可。

```xml
<bean id="userService" class="包名.UserService" autowire="byName"/>
<bean id="userDao" class="包名.UserDao"/>
<!-- 正确 -->
```

> 通过 `byType` 或 `constructor` 自动注入模式，可以给数组（array）和泛型集合（collection）进行注入。在这种情况下，容器中所有符合预期类型的自动注入候选者都被提供来满足依赖。
>
> 如果预期的key类型是 `String`，你可以自动注入强类型的 `Map` 实例。自动注入的 `Map` 实例的值由符合预期类型的所有 bean 实例组成，而 `Map` 实例的key包含相应的 bean 名称。

### 从自动注入中排除一个Bean

在每个bean的基础上，你可以将一个bean排除在自动注入之外。在Spring的XML格式中，将 `<bean/>` 元素的 `autowire-candidate` 属性设置为 `false`。容器使特定的Bean定义对自动注入基础设施不可用（包括注解式配置，如 `@Autowired`）。

你也可以根据对Bean名称的模式匹配来限制autowire候选人。顶层的 `<beans/>` 元素在其 `default-autowire-candidates` 属性中接受一个或多个模式。例如，要将自动注入候选状态限制在名称以 `Repository` 结尾的任何 bean，请提供 `*Repository` 的值。要提供多个模式，请用逗号分隔的列表定义它们。Bean定义的 `autowire-candidate` 属性的明确值为 `true` 或 `false`，总是优先考虑。对于这样的Bean，模式匹配规则并不适用。

这些技术对于那些你永远不想通过自动注入注入到其他 Bean 中的 Bean 是很有用的。这并不意味着排除在外的 Bean 本身不能通过使用 `autowiring` 进行配置。相反，Bean本身不是自动注入其他 Bean 的候选人。

### 自动注入的限制和缺陷：

当自动注入在整个项目中被一致使用时，它的效果最好。如果自动注入没有被普遍使用，那么只用它来注入一个或两个Bean定义可能会让开发者感到困惑。

- `property` 和 `constructor-arg` 设置中的明确依赖关系总是覆盖自动注入。你不能自动注入简单的属性，如基本数据、`String` 和 `Class`（以及此类简单属性的数组）。这个限制是设计上的。
- 自动注入不如显式注入精确。尽管正如前面的表格中所指出的，Spring很小心地避免在模糊不清的情况下进行猜测，这可能会产生意想不到的结果。你的Spring管理的对象之间的关系不再被明确地记录下来。
- 对于可能从Spring容器中生成文档的工具来说，注入信息可能无法使用。
- 容器中的多个Bean定义可以与setter方法或构造参数指定的类型相匹配，以实现自动注入。对于数组、集合或 `Map` 实例，这不一定是个问题。然而，对于期待单一值的依赖关系，这种模糊性不会被任意地解决。如果没有唯一的Bean定义，就会抛出一个异常。

在后一种情况下，你有几种选择。

- 放弃自动注入，改用明确注入。
- 通过将bean定义的 `autowire-candidate` 属性设置为 `false` 来避免bean定义的自动注入。
- 通过将 `<bean/>` 元素的 `primary` 属性设置为 `true`，将单个Bean定义指定为主要候选者。
- 实现基于注解的配置所提供的更精细的控制。
