# 过滤器

默认情况下，Spring 开启扫描后，会自动扫描所有 `@Component` 及其衍生的注解，被这些注解标识的类，会被 Spring 注册为 Bean 纳入容器管理。

开发者在实际开发中不希望 Spring 扫描所有的组件，那么可以自定义 filter 来修改和扩展该功能。

## 基于注解的实现

Spring 帮助开发者实现了过滤功能，这种功能被 Spring 封装在了 `@Component` 的属性中，只需要在 `@Component()` 中声明其属性 `includeFilters` 、 `excludeFilters` 即可。

具体代码如下：

```java
@Configuration
@ComponentScan(
    basePackages = "org.example", // 扫描的基础包
    includeFilters = @Filter( // 包含符合条件的组件
        type = FilterType.REGEX, 
        pattern = ".*Stub.*Repository" // 类名含 Stub 和 Repository 的类
    ),
    excludeFilters = @Filter( // 排除符合条件的组件
        type = FilterType.ANNOTATION, 
        classes = Repository.class // 排除所有标注 @Repository 的类
    )
)
public class AppConfig { 
    /* ... */ 
}
```

-  `includeFilters` 表示过滤后要保留的组件
-  `excludeFilters` 表示过滤后筛选掉的组件

无论是 `includeFilters` 还是 `excludeFilters` ，它们都具有两个属性 `type` 、`classes` 。

- `type` 表示过滤器的类型
- `classes` 表示要过滤组件的名称（但实际开发中用正则来进行模糊匹配等等）

对于 `type` 的具体值如下：

| Type（类型）               | 示例表达式                   | 说明                                                         |
| -------------------------- | ---------------------------- | ------------------------------------------------------------ |
| **注解（默认）**           | `org.example.SomeAnnotation` | 匹配**类上直接或间接标注了指定注解**的组件。例如：`@Filter(Repository.class)` 会匹配所有标注 `@Repository` 的类。 |
| **可分配的（assignable）** | `org.example.SomeClass`      | 匹配**可分配给指定类 / 接口**的组件（即继承该类或实现该接口的子类 / 实现类）。例如：`@Filter(type=ASSIGNABLE_TYPE, expression="org.example.UserService")` 会匹配 `UserService` 及其子类。 |
| **AspectJ**                | `org.example..*Service+`     | 基于 **AspectJ 类型表达式** 匹配组件。`..` 表示任意子包，`*Service+` 表示所有以 `Service` 结尾的类及其子类。 |
| **Regex（正则）**          | `org\.example\.Default.*`    | 基于**类名正则表达式**匹配组件。例如：`.*Stub.*Repository` 会匹配类名中包含 `Stub` 和 `Repository` 的类（如 `UserStubRepository`）。 |
| **自定义（custom）**       | `org.example.MyTypeFilter`   | 基于**自定义 `TypeFilter` 实现类**匹配组件。需实现 `org.springframework.core.type.TypeFilter` 接口，在 `match` 方法中定义自定义匹配逻辑。 |

对于 `classes` 则是具体的表达式（这个可以上网搜寻资料查看各个表达式的使用方法）或类名称。
