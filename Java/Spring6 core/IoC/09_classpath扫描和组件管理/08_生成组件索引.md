# 生成组件索引

本节主要针对于大型系统开发，对于小型系统来说并没有必要为组件去生成组件索引，如果这样做了反而会影响性能。

在大型系统的开发中，组件并不会想小型系统的数量那样少，这些租价数量的增加会给系统性能带来沉重的影响，因为 classpath 扫描也需要时间。

Spring 为解决这一问题，干脆不进行 classpath 的扫描（也并非不完全使用 classpath，准确的说是执行另一套程序处理的逻辑），转换成将所有组件组合成一个列表，每个组件都有对应的索引，这样做相对于 classpath 扫描，时间会大大减少。

## 如何使用组件索引

### 引入依赖

Spring 将生成组件索引的功能封装成了 jar 包，这也就需要开发者集成 jar 包。

使用 Maven 引入 jar 包：

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework</groupId>
        <artifactId>spring-context-indexer</artifactId>
        <version>6.0.8-SNAPSHOT</version>
        <optional>true</optional>
    </dependency>
</dependencies>
```

使用 Gradle 引入 jar 包：

对于 Gradle 有些不一样，**在 Gradle 4.5和更早的版本应该在 `compileOnly` 配置中声明该依赖关系。**

如下面的例子所示：

```groovy
dependencies {
    compileOnly "org.springframework:spring-context-indexer:6.0.8-SNAPSHOT"
}
```

**对于 Gradle 4.6版本后应该在 `annotationProcessor` 配置中声明该依赖。**

如以下例子所示：

```groovy
dependencies {
    annotationProcessor "org.springframework:spring-context-indexer:6.0.8-SNAPSHOT"
}
```

### 使用 spring-context-indexer

`spring-context-indexer` jar 包会在开发者对**程序编译时**，调用它，它会自动生成一个`META-INF/spring.component` 文件，并包含在jar文件中。

## 工作原理

`spring-context-indexer` 实际上是一个**注解处理器**（Annotation Processor），注意不是 BeanPostProcessor。

**该注解处理器符合 JSR 的注解处理规范**。

该注解处理器会在**编译阶段**触发，对 Spring 程序中的组件进行索引生成。
