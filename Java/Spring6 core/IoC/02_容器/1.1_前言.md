# 1.1 前言

这里是一些定义的理解，方便文档的阅读。

## 1.1.1 什么是控制反转（IOC）？

- **个人理解：**

我们在创建对象的时候，需要通过 new 关键字来创建对象，这时创建对象的权力依然在程序员手中。如下：

```java
// 创建一个User对象
User user = new User();
```

但在 Spring 框架中，我们将创建对象的权力交了出去，程序员只需要对类进行依赖注入（简称DI）操作即可，创建对象的任务交给 Spring 的IOC容器来做。这叫控制反转。

- **文档说明**：

对象仅通过构造参数、工厂方法的参数或在对象实例被构造或从工厂方法返回后在其上设置的属性来定义其依赖关系（即它们与之合作的其他对象）。然后容器在创建 bean 时注入这些依赖关系。

这个过程从根本上说是Bean本身通过使用直接构建类或诸如服务定位模式的机制来控制其依赖关系的实例化或位置的逆过程（因此被称为控制反转）。

## 1.1.2 什么是Spring IOC容器？

简单来说，管理Bean的容器就叫做IOC容器。

Spring 提供了两个包：

> **org.springframework.beans** 
>
> **org.springframework.context**

这两个包是IOC容器的基础。

在**org.springframework.beans.factory**下提供了一个接口**BeanFactory**。

BeanFactory提供一种高级配置，能够管理任何类型对象。ApplicationContext是BeanFactory的一个子接口。它增加了：

- 更容易与Spring的AOP功能集成
- Message resource 处理（用于国际化）
- 事件发布
- 应用层的特定上下文，如 `WebApplicationContext`，用于 web 应用

即BeanFactory提供了配置框架和基础功能，ApplicationContext则在其基础上增加了更多的企业特定功能。

## 1.1.3 什么是Bean？

这里提前说明方便理解。

Bean是由 Spring IOC 容器实例化、组装、管理的对象。

**注意，Bean就是对象。但是对象不一定是Bean。Bean只是应用程序中众多对象中的一个，Bean以及它们之间的依赖关系都反映在容器使用的配置元数据中。**
