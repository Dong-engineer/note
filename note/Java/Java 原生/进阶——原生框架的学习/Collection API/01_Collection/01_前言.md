# 前言

从现在开始就要开始学习 Java 原生的框架的内容了，如：集合框架，I/O流，日期，线程等等。

学习过数据机构与算法的开发者想必都听过一句话：程序=数据结构+算法，实际上确实如此，经过前辈们的整理，很多的重复性操作被前辈们封装成函数、类，以方便开发者在未来使用，但现实是变化多端的，前辈们并不能完美的预想到未来会发生什么，所以程序一直在迭代更新。但在具体的项目开发过程中，开发者需要跟据实际情况选择合适的数据结构和算法。

这里多说了一些，总之前辈将最基础的东西帮我们完成了封装，但我们仍需要耐心的去学习其底层的实现逻辑，这会更好的帮助在实际开发过程中选择合适的方法来解决问题。

而在本章节的学习中，Java 官方明确说明了开发者应该注意哪些知识点，下面会详解介绍说明。

框架是由接口和其实现类来组成的，开发者在学习过程中，应明确自己的学习目标，如下：

1. 集合的层次结构
2. 集合如何存储对象
3. 集合如何遍历存储的对象
4. 集合如何访问存储的对象
5. 如何对这些存储的对象进行分类
6. 如何防止重复值和空值的存在

而这些问题又可以细分成很多个问题，开发需要耐心并坚持学习下去。

Java 的集合框架是在 Java 2 后引入的，但是在这之前 Java 已经有处理集合数据的接口类和接口，而且这些接口依然被保留，至今依然可以使用，但 Java 是不推荐开发者再去使用的，但一些年代较早的 Java 项目中有可能会出现他们的身影，如：`Vector、Stack、HashTable` 这些都是一些老旧接口，Java 官方后面对其分别进行了改造，所以开发者如果想在维护旧系统时遇见了这些接口，应明白如何安全的去改造他们。

`Vector`：经过改造，该类实现了 `List` 接口，如果是在非并发的环境中，开发者可以安全的将其替换为 `ArrayList` 。

`Stack`：`Stack` 继承了 `Vector` ，同样的在非并发环境中，开发者可以安全的将其替换为 `ArrayDeque`。

`HashTable`：经过改造，该类实现了 `Map` 接口，在非并发的环境中，开发者可以安全的将其替换为 `HashMap` ，在并发环境中可以使用 `ConcurrentHashMap` 对其进行替换。

最后，帮助开发者解答一个疑问，当让这也是 Java 官方给出的解答——为什么使用集合，而不是使用数组？

在 Java 基础的的学习中，开发者对数组已经有所了解，在集合框架后面的学习中，部分开发者可能会有这样的问题，感觉有些问题明明可以使用数组解决为什么使用集合呢？

开发者应当明白集合不能等同于数组，这也是说集合可以干的但是数组不能干，数组能干但集合不能干，在大部分情况下数组能干的集合也能干，且功能性、扩展性，维护会更加方便。

至于二者怎么选择，这需要开发者自行掂量选择。
