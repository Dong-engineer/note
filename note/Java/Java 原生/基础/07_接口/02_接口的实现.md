# 接口的实现

上一节学习了什么是接口，怎么声明接口，本届学习如何实现接口？

## `implements`

`implements` 用于类名后，和 `extends` 用法相似，不过 `implements` 表示某个类实现了某个接口。

如下：

```java
public interface Relatable {
    public int isLargerThan(Relatable other);
}
```

```java
public class RectanglePlus implements Relatable {
    public int width = 0;
    public int height = 0;
    public Point origin;

    public RectanglePlus() {
        origin = new Point(0, 0);
    }
    public RectanglePlus(Point p) {
        origin = p;
    }
    public RectanglePlus(int w, int h) {
        origin = new Point(0, 0);
        width = w;
        height = h;
    }
    public RectanglePlus(Point p, int w, int h) {
        origin = p;
        width = w;
        height = h;
    }

    public void move(int x, int y) {
        origin.x = x;
        origin.y = y;
    }

    public int getArea() {
        return width * height;
    }
    
    // 该方法来自于Relatable接口
    public int isLargerThan(Relatable other) {
        RectanglePlus otherRect 
            = (RectanglePlus)other;
        if (this.getArea() < otherRect.getArea())
            return -1;
        else if (this.getArea() > otherRect.getArea())
            return 1;
        else
            return 0;               
    }
}
```

以上代码，可以看出在 `Relatable` 中并未对 `isLargerThan()` 进行具体的实现，在 `RectanglePlus` 具体实现了，这是接口的规定，**实现接口的类应当实现其所有方法。**

同时，还可以发现在接口的定义中参数列表接收的是一个 `Relatable` ，在抽象类就讲述过，开发者在编程时应当面向抽象编程，接口也是抽象的一种表现。这里接收一个 `Relatable` ，就提高了代码可读性和维护性、降低了耦合度，假设接收的参数是一个具体的实现类，如：`RectanglePlus`。那么当接口需要在其它类中实现时，对于 `isLargerThan()` 该方法需要在接口重载一次，重载后接受的类型是其实现类。

> 注：接口与其实现类也可以进行向上转型或者向下转型

这很麻烦，所以**面向抽象、面向接口编程是必要的。**

## 关于接口不断的发展

在上面提到了接口方法的重载，重载一次，也就意味着新增了一个方法（这里主要讲新增方法时该怎么作，重点不是重载），新增了一个方法也就表明接口跟新了，根据接口的规定，开发者必须实现其所有所有方法。这么做很麻烦而且代码维护的成本会大大增加。

### 通过 `extends` 达到新增

在旧的接口上新增新的方法变为一个新的接口，这也就意味着所有实现接口的类都需要更新。学过了继承，可以使用继承避免这种情况。

现有如下：

```java
public interface DoIt {
   void doSomething(int i, double x);
   int doSomethingElse(String s);
}
```

更新后的：

```java
public interface DoIt {

   void doSomething(int i, double x);
   int doSomethingElse(String s);
   boolean didItWork(int i, double x, String s);
   
}
```

为避免以上情况，开发者可以不去新增方法而是去新增一个接口，让旧的接口继承新的接口，如下：

```java
public interface DoItPlus extends DoIt {

   boolean didItWork(int i, double x, String s);
   
}
```

这样做即达到了接口新增方法的目的，同时保证了不用重新写那些实现了 `DoIt` 但是并不需要去实现 `DoItPlus` 的类，对于实现 `DoItPlus`  的类，开发者只需要在其类的内部新增一个方法即可。

###  通过 `default` 实现新增

除此之外，Java 还提供了一种方法，就是使用 `default` 修饰符。

 `default` 所修饰的方法不必再实现类中去实现具体的方法体，因为 Java 规定了 `default` 所修饰的方法需要在其自身接口中是需要有一定的实现细节的，如下：

```java
public interface MyInterface {
    void print();

    default void printName() {
        System.out.println("Dong");
    }
}
```

```java
public class Test18 implements MyInterface{
    @Override
    public void print() {
        System.out.println("Hello World");
    }

    // 可以不用重写
    //@Override
    //public void printName() {
    //    System.out.println("I am Test18");
    //}

    public static void main(String[] args) {
        MyInterface myInterface = new Test18();
        myInterface.print(); // Hello World
        myInterface.printName(); // Dong
    }
}
```

## 接口的`static`

这里不再多讲述，和继承一样，只记住一个要领：`static`修饰的东西只属其类（接口也是类）本身。

所以，当开发者考虑到接口需要有自己本身的实现细节的时候使用 `static` 即可。

## 实际开发中的接口（不要漏下）

Java倡导开发者在实际开发中使用，通过接口去实现方法的细节。

即 Java 倡导开发者通过接口去进行开发，为了更好的去开发软件系统，那么这也就需要开发者去预想、设计接口。

但这并不意味着要吧整个系统的所有接口都要预想、设计出来，这是不合理的，需求后续发生了变更，那么提前设计的接口可能需要进行大规模的调整，甚至会推倒重来。

**所以一名合格的开发者（架构师）应当在软件系统开发的开发前期去预想核心架构和关键接口**。然后在开发过程中逐步完善细节。要根据项目的规模、需求的稳定性以及团队的协作方式，灵活地平衡设计的前瞻性和灵活性。
