# 默认的初始化回调和销毁回调

Spring 建议开发者不去实现初始化回调和销毁回调对应的接口，这也就导致了每个开发者对初始化回调和销毁回调的方法命名是不统一的。

Spring 为解决这个问题，规定了规范的明明标准。

## `default-init-method=""`

在XML文件中，在 `<bean/>` 标签的里面可以使用 `default-init-method=""` 来表示某个 Bean 的默认初始化回调方法，如果开发者在容器级标签中使用，比如 `<beans/>` ，那么该容器内的所有 Bean 的初始会回调方法默认的名称就是其对应的属性值。

销毁回调亦是如此。

## 配置了多个初始化回调和销毁回调

如果开发者使用不同的方式为 Bean 配置了多个初始化回调和销毁回调，那么 Spring 将会按照以下顺序进行执行，但是不建议开发者去配置多个初始化回调和销毁回调。

顺序如下：

1. 被注解的方法
2. 实现对应接口后重写的方法
3. XML文件配置的方法
