# 主动抛出异常

上节内容说了 Java 倡导开发者去预想异常可能发生的位置，这样会使用大量的 `try...catch` ，这不仅会增加资源的消耗还降低了代码的阅读性。

但是 Java 允许开发者主动抛出异常，这样在编译时 JVM 就提前知道了某个方法其抛出的具体异常是什么了，在运行时，如果该方法发生了异常也无需担心，因为开发者已经提前预想到了，并对其进行捕获。

## `throws和throw`

### throws

- **作用**：在方法签名中**声明该方法可能抛出的异常类型**并将其异常向上抛出，告知调用者需要处理这些异常。

- **语法**：`返回类型 方法名(参数列表) throws 异常类型1, 异常类型2... { ... }`

- **使用场景**：
  - 方法内部调用了其他声明了受检异常的方法，且当前方法不想处理这些异常。
  - 自定义方法需要明确告知调用者可能出现的异常。

### throw

- **作用**：再方法体内抛出具体的异常对象，告知该方法其将会抛出什么异常对象。

- **语法**：`throw new 异常类型("信息")`

- **使用场景**：
  - 参数校验失败（如传入非法参数）。
  - 业务逻辑不满足条件（如余额不足）。
  - 封装底层异常为更上层的业务异常。

### 总结

- **`throw`** 是**动作**：触发异常，让程序进入异常处理流程。
- **`throws`** 是**声明**：告知调用者 “我可能会抛出这些异常，你需要处理”。
