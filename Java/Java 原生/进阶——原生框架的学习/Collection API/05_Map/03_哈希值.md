# 哈希值

 哈希值指的是**通过哈希函数对任意长度的输入数据，计算出固定长度的输出值，也叫散列值**。

- 核心特性：
  1. **固定长度**：无论输入数据是 1 KB 的文本还是 1 GB 的文件，同一哈希函数输出的哈希值长度始终一致（如 `MD5` 输出 128 位、`SHA-256` 输出 256 位）。
  2. **确定性**：相同输入在同一哈希函数下，必然得到相同哈希值。
  3. **雪崩效应**：输入数据的微小变化（如一个字符修改），会导致哈希值发生巨大改变。
  4. **不可逆性**：无法从哈希值反向推导出原始输入数据。
- **典型用途**：数据校验（如文件完整性验证）、密码存储、哈希表（`HashMap、Dictionary`）的键值映射。

# 哈希函数

是**哈希算法的具体代码 / 程序实现**，是可直接调用的函数。

# 哈希算法

哈希算法并不是指具体某一种算法的，而是一套计算规则或者说是一个抽象的数学模型。
比如 MD5、SHA-256、CRC32 都属于不同的哈希算法。

哈希算法并不是加密算法，开发者要明白什么是加密算法，加密算法能将数据加密，其必定会有解密算法，上面讲述到哈希值是不可逆，故此哈希值是无法通过逆向解密的。

# 哈希冲突

哈希冲突指的是不同数据通过同一哈希函数后，得到了相同的哈希值。

# 哈希值真的不可逆吗？

其实哈希值并非是不可逆的。

首先开发者应明确知道，哈希值是通过**通过哈希函数对任意长度的输入数据，计算出固定长度的输出值，也叫散列值**。

以 MD5 为例，设计算结果为 2^128^ （后面称其为输出空间，术语），好的现在开发者你已明确知道了输出空间为 2^128^ 种可能。而输入空间则是无限，那么从输入空间到输出空间中的操作规则需要开发者自行去定义。这也就意味这无限的可能对应上有限的可能必定是多对一的结果。

而在输入空间转换至输出空间中需要有明确的转换逻辑规则，提取出特征性强的数据，丢弃特征性不强的数据。

对于想要进行解密的开发者来说解密后你将会得到无数种可能。又因为雪崩效应，在这无数种可能中，每一种可能几乎都是没有关联的。
