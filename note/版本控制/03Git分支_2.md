# Git 分支

本节开发者将会学习到 Git 分支的合并。

当开发者在某个阶段需要对项目往不同的方向进行开发，那么此时开发者的将会 2 个或 2 个以上的分支。且每一个分支都经过了严格的测试，那么开发者想要将这些新增、修改、删除的内容合并在一起成为一个完成系统。这就需要使用 Git 的合并功能。

## Git 分支的合并

分支的合并需要两个分支，合并分支流程如下：

1. 先选择一个分支作为基底，再选择一个分支作为目标（这里假设基地分支是 `master`，目标分支是 `testing`）
2. 执行 `git checkout master` 命令切换到基底分支
3. 执行 **`git merge testing`** ，合并分支
4. Git 会检测校验两个分支各自的信息，无冲突，会提示合并成功

```bash
# 切换分支
$ git checkout master
Switched to branch 'master'

# 合并分支
$ git merge testing
# 合并后的具体信息
# updating 表示修改了 commit 的 SHA 的哈希校验和
Updating f42c576..3a0874c
# Fast-forward 表示快速合并，向前移动了 master 指针的位置
Fast-forward
 index.html | 2 ++
 1 file changed, 2 insertions(+)
```

通过以上内容，开发者了解到，Git 合并分支的方式通过移动 `master` 指针的指向来完成的合并（事实确实如此，但不仅仅是这样）。

观察下图，`testing` 分支指针领先 `master` 分支指针，二者依然属于同一开发方向上。

![](./img/testing 分支领先图.png)

Git 会直接将 `master` 分支的指针直接指向 `testing` 所指向的提交记录——即 C5。
