# 启动回调与关闭回调

本节讲述启动回调，当然有启动回调，自然也有关闭回调，先了解启动后关闭自然会明白。

Bean 的启动回调和 Bean 的初始化回调不一样。

Bean 的启动回调在 *01_Bean的生命周期* 一节中已经明确说明不在讲述。

下面详细讲述。

## Bean 的启动

在详细学习接口之前，作者补充一些内容。

在 Spring 的原文中是这样说明的：在容器 `ApplicationContext` 本身收到信号的时候，会调用级联到定义在程序中的所有 `Lifecycle` 实现，级联调用这一过程是通过  `LifecycleProcessor` 进行委托的。

但是实际上容器 `ApplicationContext` 在启动时会有一系列工作准备，如：Bean 的加载和定义、Bean 的创建等等。这些工作在 Bean 的启动回调之前是理所应当的，如果一个 Bean 在一开始都没有被准备好，那么怎么去启动并使用。

这道这些就开始 `Lifecycle` 及其子类还有实现的学习。

## `Lifecycle`

`Lifecycle` 接口——只要有生命周期需求的对象（Bean） 都可以去实现该接口，里面包含生命周期的的一些基本方法。

接口如下：

```java
public interface Lifecycle {
	
    // 启动
    void start();
    
    // 关闭
    void stop();
    
    boolean isRunning();

}
```

与此同时 Spring 在其基础上扩展了生命周期处理器 `LifecycleProcessor` ，该接口继承了 `Lifecycle` 接口。

### 具体的使用

假设开发者现在需要一个用户类，在其被启动（使用）的时候自动打印其信息：

```java
public User implements Lifecycle {
    
    private String name;
    
    public User() {
        
    }
    
    public void setName(String name) {
        this.name = name;
    }
    
    public String getName() {
        return this.name;
    }
    
    @Override
    public void start() {
        System.out.println("用户名：" + this.getName());
    }

    @Override
    public void stop() {
        System.out.println("用户名：" + this.getName() + "结束使用");
    }
}
```

测试类：

```java
public class UserTest {
    
    // 配置类，用于定义Spring Bean
    @Configuration
    static class AppConfig {
        @Bean
        public User user() {
            User user = new User();
            user.setName("张三"); // 设置用户名
            return user;
        }
    }
    
    public static void main(String[] args) {
        // 初始化Spring容器
        ApplicationContext context = new AnnotationConfigApplicationContext(AppConfig.class);
        
        System.out.println("Spring容器初始化完成");
        
        // 调用容器的start()方法，会级联调用所有Lifecycle Bean的start()
        if (context instanceof Lifecycle) {
            ((Lifecycle) context).start();
        }
        
        // 模拟应用运行
        try {
            Thread.sleep(2000);
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
        
        // 调用容器的stop()方法，会级联调用所有Lifecycle Bean的stop()
        if (context instanceof Lifecycle) {
            ((Lifecycle) context).stop();
        }
        
        // 关闭容器
        ((AnnotationConfigApplicationContext) context).close();
    }

}
```

```cmd
Spring容器初始化完成
用户名：张三
用户名：张三结束使用
```

在以上代码你会发现，必须显示调用容器的 `start()` 的方法才会级联调用其他 `Lifecycle` 的 `start()` 。后面回讲述自动调用。

##  `LifecycleProcessor` 

接口定义如下：

```java
public interface LifecycleProcessor extends Lifecycle {

    void onRefresh();
    
    // 和stop()发生的时间是不一样的，但都是关闭，后面讲述关闭的时候细说
    void onClose();

}
```

## `Phased`

如果一个 Bean A 依赖了 Bean B ，那么 Bean B 的生命周期一定发生在 Bean A 前面。但是如果两个 Bean 之间没有明确的依赖关系呢？

Spring 定义 `Phased` 接口，其里面定义了方法决定了 Bean 的先后顺序。

接口定义如下：

```java
public interface Phased {

    int getPhase();

}
```

实现了该接口的 Bean 重写 `getPhase()` 方法返回一个值，**根据值得大小来决定启动回调得顺序**。

**对于启动来说，值越大越优先**。

**对于关闭来说，值越小越优先**。

具体如何使用后面讲述不要着急。

## `SmartLifecycle`

在 *01_Bean生命周期* 中开发者可以发现，有两处启动回调，这是因为 Spring 中的 `SmartLifecycle` 接口，该接口同样可以实现启动回调，但是和 `Lifecycle` 不同的是， `SmartLifecycle` 可以更加灵活的控制 Bean 的生命周期回调， `SmartLifecyele` 不仅继承了 `Lifecycle` ，还继承了 `Phased`。

就扣定义如下：

```java
public interface SmartLifecycle extends Lifecycle, Phased {
	
    // 自启动
    boolean isAutoStartup();

    // 关闭回调
    // 这里开发者不难发现stop()接收的参数是一个 callback
    // 无论stop()方法体内书写了什么代码，最后都要去调用 callback.run()
    // 因为这保证了stop()方法完整的实现 => 即异步回调
    void stop(Runnable callback);
}
```

在实际开发中，通常让 Bean 去直接实现 `SmartLifecycle` ，因为 `SmartLifecycle` 能更加灵活的控制 Bean 的生命周期。

继续使用上面的例子，如下：

```java
import org.springframework.context.SmartLifecycle;

public class User implements SmartLifecycle {
    
    private String name;
    private boolean isRunning = false; // 用于跟踪是否正在运行
    
    public User() {
        
    }
    
    public void setName(String name) {
        this.name = name;
    }
    
    public String getName() {
        return this.name;
    }
    
    @Override
    public void start() {
        System.out.println("用户名：" + this.getName());
        isRunning = true; // 启动后标记为运行中
    }

    @Override
    public void stop() {
        System.out.println("User停止");
        isRunning = false; // 停止后标记为非运行中
    }

    @Override
    public boolean isRunning() {
        // 返回当前组件是否处于运行状态
        return isRunning;
    }

    @Override
    public int getPhase() {
        // 定义在生命周期中的执行阶段，值越小越先启动，越晚停止
        return 0;
    }

    @Override
    public boolean isAutoStartup() {
        // 是否应该在Spring上下文启动时自动启动
        System.out.println("自动启动");
        return true; // 自动启动
    }

    @Override
    public void stop(Runnable callback) {
        // 带回调的停止方法，用于异步停止场景
        stop(); // 调用普通的停止方法
        callback.run(); // 执行回调，通知Spring该组件已停止
    }
}
```

测试类：

```java
public class UserLifecycleTest {

    // 配置类，用于定义Spring Bean
    @Configuration
    static class AppConfig {
        @Bean
        public User user() {
            User user = new User();
            user.setName("测试用户");
            return user;
        }
    }
    
    public static void main(String[] args) {
        System.out.println("===== 启动Spring容器 =====");
        // 创建Spring容器，会自动触发SmartLifecycle的自动启动
        AnnotationConfigApplicationContext context = new AnnotationConfigApplicationContext(AppConfig.class);
        
        System.out.println("\n===== 从容器中获取User实例 =====");
        User user = context.getBean(User.class);
        System.out.println("当前User是否在运行: " + user.isRunning());
        
        System.out.println("\n===== 停止Spring容器 =====");
        // 关闭容器，会触发停止相关的回调方法
        context.close();
        System.out.println("容器关闭后，User是否在运行: " + user.isRunning());
    }

}
```

对于以上代码，开发者不难发现，在测试类中并没有像在 `Lifecycle` 的测试类中显示调用容器的 `start()` ，这是因为 `SmartLifecycle` 会自动调用 `start()`。
