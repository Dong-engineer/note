# 通配符

在*泛型方法*中讲到了*有界类型参数*，在其里面的内容讲到了 *单个边界、多个边界*，通配符和其相似，但*有界类型参数* 是明确规定 `T` 的类型边界，如下：

```java
 <T extends B1 & B2 & B3>
```

这表明了 `T` 只能是  `T` ，且`T` 是 `B1` 的子类（注意是子类，不能是子类的子类）且实现了 `B2、B3` 接口。

即*有界类型参数* 是已知了 `T` ，限定了 `T` 的范围。

但是通配符不一样，通配符是不知明确的 `T` ，根据其大致范围匹配符合要求的 `T`。

## 声明通配符

如下：

```Java
<? extends Number>
```

这会匹配 `Number` 的本身及其任何子类（注意是子类，不能是子类的子类）。

通配符分三种：

1. 无界
2. 上界
3. 下界

上面那段代码属于上界，即 `Number` 是 `?` 区间的上界。（[`Number`,  `Number的子类`]） 

### 无界通配符

无界通配符，就是没有边界，直接一个`?`。

```java
List<?> list;
```

#### 用法

无界通配符表示任意类型。常用于不需要关心泛型具体类型的场景，例如打印集合中的所有元素。

不能向`List<?>`中添加元素（除了`null`），因为编译器无法确定具体类型。

### 上界通配符

```java
<? extends T>
```

#### 用法

上界通配符表示类型必须是`T`或其子类。用于限制泛型的上限，例如接收一个`Number`及其子类的集合。

可以读取元素（返回类型为`T`），但不能添加元素（因为无法确定具体子类类型）。

### 下界通配符

```java
<? super T>
```

该含义就表示[ `T的父类` , `T` ]。

#### 用法

用于写入数据的场景，可以向其中添加`T`类型的元素（或者其子类元素），但读取时只能将元素当作`Object`处理。

## PECS 原则（Producer Extends, Consumer Super）

根据不同通配符的利弊，开发者们应道遵守 PECS 原则。

- 如果需要从泛型集合中读取数据，就使用`? extends T`（生产者使用 extends）。
- 如果需要向泛型集合中写入数据，就使用`? super T`（消费者使用 super）。
- 要是既需要读取又需要写入数据，那就不要使用通配符。

## 总结

| 通配符类型 | 示例                | 允许读取的类型 | 允许写入的类型 | 使用场景         |
| ---------- | ------------------- | -------------- | -------------- | ---------------- |
| 无界通配符 | `List<?>`           | `Object`       | 禁止           | 不关心元素类型时 |
| 上界通配符 | `List<? extends T>` | `T`及其子类    | 禁止           | 读取数据         |
| 下界通配符 | `List<? super T>`   | `Object`       | `T`及其子类    | 写入数据         |
