# 字符串

字符串学习到这里，对于开发者来说应景不陌生了，但是开发者对于字符串的底层创建有可能不太了解，本节会介绍。

## String

开发者都知道`String`是字符串类，所以在 Java 中字符串是以对象的形式存在的。

### 创建String对象

创建一个`String`类型对象，最常见的方式如下：

```java
String greeting = "hello world";
```

使用这种方式创建字符串对象，编译器会自动帮助开发者`new`一个`String`对象，其内容为 `hello world`。

可能有人会认为等效代码如下：

```java
String greeting = new String("hello world");
```

**实际这种理解是错误的。**

除此之外，java还允许开发者使用不同的参数（称为源），来进行创建字符对象。

如下：

```java
char[] helloArray = { 'h', 'e', 'l', 'l', 'o', '.' };
String helloString = new String(helloArray);
System.out.println(helloString);
```

> *注意：*`String` *类是不可变的，因此一旦创建它，就无法更改* `String` *对象。*`String` *类有许多方法，其中一些方法将在下面讨论，这些方法似乎可以修改字符串。由于字符串是不可变的，因此这些方法的真正作用是创建并返回一个包含作结果的新字符串。*



## 字符常量池（重点）

在上面的最后引用中，讲明了 Java 中`String`类是不可改变的，这非常棒的一个决策，下面一点一点来说。

### 为什么不可变？

这是`String`类源码所决定的，源码如下：

```Java
public final class String
    implements java.io.Serializable, Comparable<String>, CharSequence {
    private final byte[] value;  // 存储字符串内容的字节数组
    private final byte coder;    // 编码方式：0 表示 Latin-1，1 表示 UTF-16
}
```

**不难发现，Java 将使用了 `final byte[] value`存储字符串内容，所以这就决定了`String`类的对象不可被修改**。

那么Java为什么将`String`类型定义为不可变的呢？

1. 不可改变的变量在多线程中天然就是安全的
2. 优化内存（这里有关到字符常量池，后面讲述）

第一点很好理解，就不再多讲述，主要是字符常量池。

### 字符常量池

Java 将内存主要分为三大部分（后面学习JVM的时候会学到的，并不止这三）**堆区、栈区、方法区（又称元空间）**。好了到此为止，多的不再讲述，配个图方便小白理解。

![](C:\Users\86198\Desktop\学习\Java原生\基础\05_数字和字符串\img\字符常量池图示.png)

假设开发者此时声明了一个字符串变量，如下：

```java
String str = "hello";
```

JVM 会优先在字符常量池中寻找是否有`"hello"`字符串常量。

如果没有，直接在字符常量池中创建一个，将该字符串的地址赋值给变量`str`。

如果有，那么直接将地址赋值给给变量`str`。

**这么做就保证内存的浪费，避免了字符串重复创建。**

### 字符什么时候存在字符常量池中呢？

考过软考证的开发者（不是信息那一类的哦）应该是知道的。在编译阶段，会对程序进行词法分析，语法分析、语义分析，在进行词法分析时，编译器会分析程序中的字符、符号、等等。

**也就是在编译阶段，Java会将程序中所有字符串添加到字符常量池中。**

## 字符串创建对象（重点）

字符串创建对象，分为两类，一种是静态创建字符串，另一种是动态创建字符串。

二者的区别：**静态创建字符串在编译时就已经将字符串加入字符常量池中。**

**动态创建字符串是在运行时创建字符串对象，且目标字符串是不会存储到字符常量池中。**

### 静态创建字符串

#### 字面值创建字符串

在之前的 *对象* 章节中学习过，对象之间的对比，使用`==`实际比较是对象的内存地址。跟据以上的内容，那么，开发者可以检测一下当两个字符串的内容相同时，地址是否相同。

如下：

```java
String str = "hello";
String str1 = "hello";
// 这样做IDE会提示你警告，因为正常来比较两个字符串的值是否相等应该使用 equals()
System.out.println(str==str1); // true
```

结果为 `true` ，所以两个对象的地址是一样的。

**一旦字符串被创建是不会被删除的，该字符串会被存储在字符串常量池中等待下次被使用。**

```java
String str = "hello";
str = "hello1";
System.out.println(str.hashCode());	// -1220935265
System.out.println("hello".hashCode()); // 99162322
```

这里，创建了`str`变量，并重新赋值，`"hello"`字符串并没有被删除，其依然在字符常量池中存在。

### 动态创建字符串

#### new 创建字符串对象

```java
// new 创建，在堆中
String s3 = new String("hello");
System.out.println(s1 == s3);  // false
```

一个阶段一个阶段，一行一行代码来讲述。

编译阶段，JVM 检测到程序中含有`"hello"`字符串，如果字符常量池中没有该字符串，那么将其加入到字符串常量池中，有则无需此操作。

运行阶段，程序使用了`new`，则 JVM 会在堆区中开辟一片空间，这片空间分为两部分，**一部分叫做头，一部分叫做数据部分**，头部份存放 `s3`该变量所指向的在堆区中的地址，数据部分存放数据值（也就是`"hello"字符串`）。

所以这也就是为什么 `s1==s3` 为false。

#### 通过数组创建字符串对象

正如图所示，通过数组创建字符串对象是特殊的。

代码如下：

```java
char[] c = {'h','e','l','l','o'};
String s4 = new String(c);
c[2] = 's';
System.out.println(c); // heslo
System.out.println(s4); // hello
```

一个阶段一个阶段，一行一行代码来讲述。

对于字符需要知道的是，JVM 并不会将字符加入到字符串常量池中，**所有的`char`类型的字符值，它的值直接存储在栈或对象字段中**。

所以在编译阶段 JVM 是不会对以上代码所出现的字符加入到字符常量池中的。

`c`变量存储其对象数组在堆区中的地址，在堆区中开辟一片连续的空间用来存储数组内容，其头部分存储`c`变量所指向的地址，数据部分每一个地址存储一个对应得到字符。

`s4`变量通过`new`在堆区中开辟一片空间，同时接受`c`作为参数，经过字符之间的算法组合最终 `s4`所对应的对象的数据部分存储 `hello` 字符串。

如果按以上所说，那么开发者在修改 `c`变量所对应的参数，`s4`逻辑上来说也应随之改变，但是当开发者打印输出后发现，`s4`变量是没有改变的。

**这是因为 Java 确保了 `String`类型的不可修改性，在 `s4`new对象的时候，将`c`的数据部分进行了复制，创建了一个新的副本，也就是说 `s4`实际是根据`c`变量的一个副本进行创建字符串**



### intern()

讲到`intern()`，有些东西还是要细说一下。

上面的图是 Java 6前的模型所示，但是在 Java 7+后 Java 将字符串常量池实际的物理内存地址，移动到了堆区中。

不过上图中的内容核心逻辑是正确的。

因为 Java7+ 前后的将字符常量池的移动，所以有些机制也随之改变。这里分开讲。

####  intern()是干什么的

`intern()` 也是创建字符串对象，但是他和`new`创建字符串不一样，一样的是都是在**运行时创建**。

下面详细介绍。

#### Java 7+ 前

`intern()`返回字符串在字符常量池中的地址。

先来一段代码：

```java
String str1 = new String("hello");
String str2 = str1.intern();
String str3 = "hello";

// 比较引用
System.out.println(str1 == str2); // 输出 false
System.out.println(str2 == str3); // 输出 true
```

以上代码先是通过`new`创建了`hello`字符串，经过以上的学习开发者是知道 `new` 创建字符串属于动态创建字符串，**那么也就意味着`hello`在编译阶段会被加入到字符串常量池中**。

后面`str1.intern()`，`str1`调用了`intern()`，**`intern()`会检测字符常量池中是否存在`hello`，如果不存在，`intern()`会将其加入到字符常量池中。如果存在直接返回其地址。**

所以在最后的`str1 == str2`结果为false，`str2 == str3`结果为true。

#### Java 7+ 后

`intern()`返回堆中原始字符串的对象。

先来一段代码：

注：这段代码是最初作者本人根据字符串创建逻辑，让AI去生成的实验代码，但是实际输出为false，这样从侧面反映了AI在2025年这年并不能完全取代程序员，很多小细节还是需要人来处理，但是写这一整本笔记的时候AI确实对作者有不少帮助

```java
String s1 = new String("hello"); // 在堆中创建对象
String s2 = s1.intern(); // 直接记录堆中引用
System.out.println(s1 == s2); // false
```

以上代码可以看出，`new`创建对象的过程不再叙述，后面会发现通过`s1.intern()`返回的对象赋值给`s2`，`s1==s2`结果为: `false`。

与 Java 7+前的`intern()`不同的是，Java 7+后 Java优化了`intern()`的机制。

**当`s1`所存储的`hello`字符串在字符常量池中存在的时候，优先返回`hello`字符串在常量池中的地址，如果常量池中没有`hello`字符串，不再将`hello`字符串复制到常量池中，而是直接返回其最原始的对象地址。**

如下代码测是`intern()`：

```java
char[] c = {'h', 'e', 'l', 'l', 'o'};
String s4 = new String(c);          // 堆中创建 "hello"，常量池无此字符串
String s5 = s4.intern();            // 将 s4 的引用记录到常量池
System.out.println(s4 == s5);       // true，s4 和 s5 指向同一对象
```

这样写代码，就避开了在编译阶段 JVM 将`hello`字符串添加到字符常量池中。

为了形成对比，如下代码：

```java
char[] c = {'h', 'e', 'l', 'l', 'o'};
String s4 = new String(c);
String s5 = s4.intern();

// 验证常量池中的字符串是否与字面量相同
String literal = "hello";
System.out.println(s5 == literal);  // true，说明常量池中的字符串与字面量共享引用
```

#### 补充

在 Java 7+后提到了**最原始的对象地址**，可以使用如下代码验证：

```java
char[] c = {'h', 'e', 'l', 'l', 'o'};
String s4 = new String(c);
String s5 = new String(c);
String s6 = s4.intern();
String s7 = s5.intern();
System.out.println(s4 == s5); // false

System.out.println(s6 == s4); // true
System.out.println(s6 == s5); // false

System.out.println(s7 == s6); // true
System.out.println(s7 == s4); // true
System.out.println(s7 == s5); // false
```

通过代码可以看出，无论是通过 `s4` 还是 `s5` 调用`intern()`创建的字符串，**只要是通过 `intern()`其最终指向的地址都是最初、最原始的那个对象。**

### 通过 `"+"`创建字符串

在前面的学习中，开发者应该也知道，字符串在创建时是可以使用 `+` 来进行拼接的。

但是通过 `+` 来拼接字符串也分两种情况，和上面一样，一种静态创建，一种动态创建。

#### 静态创建

**字符串中不包含任何非常量表达式。**

如下：

```java
String s = "Hello" + "World";  // 编译期优化为 "HelloWorld"
final String a = "Hello";
final String b = "World";
String s = a + b;  // 编译期优化为 "HelloWorld"
```

#### 动态创建

与静态创建相反，**字符串中包含任何非常量表达式。**

如下：

```java
String a = "Hello";
String b = "World";
String s = a + b;  // 运行时动态拼接，等价于 new StringBuilder(a).append(b).toString()
```

#### 总结

| **拼接方式**        | **执行时机** | **是否创建新对象**   | **示例**                                    |
| ------------------- | ------------ | -------------------- | ------------------------------------------- |
| 字面量 + 字面量     | 编译期       | 否（直接引用常量池） | `String s = "a" + "b";`                     |
| 字面量 + final 变量 | 编译期       | 否（直接引用常量池） | `final String a = "a"; String s = a + "b";` |
| 变量 + 变量         | 运行时       | 是（堆中创建新对象） | `String a = "a"; String s = a + "b";`       |
| 变量 + 方法调用     | 运行时       | 是（堆中创建新对象） | `String s = "a" + getStr();`                |

#### 注意事项

- **性能差异**：编译期优化的拼接效率更高，因为避免了运行时 `StringBuilder` 的开销。
- **常量池影响**：编译期生成的字符串字面量会进入常量池，而运行时动态拼接的字符串不会（除非显式调用 `intern()`）。
