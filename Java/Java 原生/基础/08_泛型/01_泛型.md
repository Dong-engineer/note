# 泛型

本节开始泛型的学习，泛型在实际中开发中很常用，其很好用。

泛型的核心思想是：**类型参数化**。

将类型进行参数化，在前面的学习都知道，类型应该是固定某一个类，怎么能参数化呢？参数化了意味着什么呢？。

一点一点来学习。

## 为什么使用泛型？

### 泛型的思想

为什么使用泛型简而言之就是泛型可以将类型 参数化（当然这是废话），下面详细讲述。

假设开发者有一个类 `MyClass` ，对于 `MyClass` 是一个存储多个对象的集合且存储的对象类型是不一样的。

根据以上要求，这也就意味 `MyClass` 需要达到两个目的：

1. 存储多个对象
2. 存储的对象类型是不一的

一个一个问题解决，存储多个对象这个简单——数组，数组就可以存储多个对象，但是数组**只能存储该类型或其子类型的元素**：

如下：

```java
// 只能存储int类型
int[] i = {1,2,3,"1"}; // 报错——不兼容的类型: String无法转换为int
```

那么怎么存储类型不统一的对象呢？

身为一名天才的开发者——正在阅读的每一个人，想到了 `Object` ，可以直接将数组声明为 `Object` ，因为所有的类都隐式继承 `Object` ，除了基元数据类型（但是可以用包装类）。

当然以上内容还有下面 `MyClass` 代码是帮助开发者思考的，实际开发中直接使用 Java 提供的 `Collection` 集合框架即可。

于是这样写：

```java
public class MyClass {
    
    Object[] obj;
    
    public MyClass() {
        // 初始默认为10
        this.obj = new Object[10];
    }
    
    // 来一个添加的方法，默认添加到末尾
    public void add(Object obj) {
        // 方法体不再书写了，和数据结构的链表操作一样
        // 向obj中添加数据
    }
    
    // 再来一个获取元素的方法，根据元素位置获取，开始下标为0
    public Object get(int i) {
        // ...
    }
    
    // 其他扩容等操作就不写了
}
```

好核心的逻辑就是这样，那么在获取元素的时候，如下操作：

```java
public static void main(String[] args) {
	MyClass myClass = new MyClass();
    myClass.add("123");
    myClass.add(123);
    
    // 获取元素
    // 这里注意，这是向下转型 这里是：父类对象赋值给子类引用，需要强制转换
    String str = (String) myClass.get(0);
    int i = (Integer) myClass.get(1);
}
```

这样确实达到了上面的两个需求，但是在获取元素和添加元素时很容易发生错误，这时泛型就登场了。

泛型直接可以让**类型 参数化**，这是泛型的核心思想。

### 声明泛型类

如下就是声明一个泛型类：

```java
// 使用泛型就可以这样写
public class MyClass<T> {
    
    T[] t;
    
    public MyClass() {
        this.t = new T[10];
    }
    
    public void add(T t) {
    }
    
    // 根据接受的类型参数，返回一个对应的值
    public T get(int i) {
    }
    
}
```

这样做就确保了 `MyClass` 的方法会根据其接受的类型参数变化而变化。

```java
public static void main(String[] args) {
    
    // 不能使用int，泛型不可以是基元数据类型
	MyClass<Integer> myClass = new MyClass<Integer>();
    myClass.add(1);
    myClass.add(2);
    
    // 不用强转
    int i = myClass.get(1);
    int a = myClass.get(2);
}
```

避免了开发者在书写程序是去进行强制转化所发生类型不兼容的问题。

### 类型参数化的规则

- E - 元素
- K - 键
- N - 数字
- T - 类型
- V - 值
- 等等（后面遇到了就会知道）

## 泛型详解

上面已经学习过了泛型，这里就开始深入了解泛型。

仔细阅读上文的代码，不难发现，当 `MyClass` 接收了一个参数化的 `String ` 类型，那么也就意味着只能存储 `String` 类型的对象。

在后面 Java 的  `Collection` 集合框架的学习中也是如此。那么会有很多小白就疑问了？这样做岂不是多此一举吗？

### 编译错误、运行时错误

其实在前面的学习，乃至后面的学习，会有很多这样的疑问，这样做的目的是：

1. 保证程序在运行时无误，如果一旦在运行时发生错误，那么很可能发生不可估量的错误。
2. 编译错误容易修改，运行时错误很难返现、并修改。
3. 保证了类型在运行时时安全的。

**所以使用了泛型的话，要确保其使用方式是正确的。**

**如果说是为了存储任何类型的对象，开发者可以使用 `Object` 将其参数化。**

### 原始数据类型

Java 已经帮开发者完善了泛型。

在创建一个类时不一定非要使用泛型，如下：

```java
Box rawBox = new Box();
```

这种创建对象就叫做**原始数据类型**，又称 **Raw 数据类型**。

如果使用了泛型就叫做**参数化类型**，如下：

```java
Box<String> stringBox = new Box<>();
```

**参数化类型赋值给原始数据类型是可行的**，如下：

```Java
Box<String> stringBox = new Box<>();
Box rawBox = stringBox;               // OK
```

但是**原始数据类型赋值给参数化类型是不可行的**，如下：

```java
Box rawBox = new Box();
Box<Integer> intBox = rawBox; // 这里会警告，主要看运行时是否符合其逻辑
```

下面就是原始数据类型赋值给参数化类型运行时错误：

```java
Box<String> stringBox = new Box<>();
Box rawBox = stringBox;
rawBox.set(8);  // 报错
```

```java
public class WarningDemo {
    public static void main(String[] args){
        Box<Integer> bi;
        bi = createBox();
    }

    static Box createBox(){
        return new Box();
    }
}
```

这样写绕过了编译时泛型类型检查，因为语法是没有错误的。但在运行时，发现尝试将 `Integetr` 类型的数据存储到一个 `String` 类型里面，这是错误的行为。

综上，Java 倡导开发者在实际开发时不要这书写代码，**准确的来讲直接避免使用原始数据类型**。

在这里作者表示 Java 官方说的对，既然身为开发者的你把某一个类让其变为了泛型类型，为什么还要去尝试创建其原始数据的对象呢？或者一开始将其变为泛型类型是非必要的呢？

## 泛型方法

### 声明泛型方法

除了将某一个类使其变为泛型类型，还可以将某个方法让其变为泛型方法，如下：

```java
public class GenericMethodExample {
    // 泛型方法：打印数组元素
    public static <T> void printArray(T[] array) {
        for (T element : array) {
            System.out.print(element + " ");
        }
        System.out.println();
    }
}
```

泛型方法和泛型类型的目的是一样的，都是为了使类型参数化，避免运行时类型转换错误。

泛型方法不仅可以像上面的代码那样书写还可以如下使用：

```java
public class GenericMethodExample {
    
    public <T> void printArray(T[] array) {
        for (T element : array) {
            System.out.print(element + " ");
        }
        System.out.println();
    }

    // 泛型方法：返回两个值中的较大者（需实现 Comparable 接口）
    public <T extends Comparable<T>> T max(T a, T b) {
        return (a.compareTo(b) > 0) ? a : b;
    }
}
```

**当某个类并非必须成为泛型类，而其某一方法需要泛型化，这时就需要使用泛型方法了。**

### 调用泛型方法

经过泛型类型的学习，开发者知道泛型类型的使用方式，对于泛型方法用法是一样的，标准的语法如下：

```java
public static void main(String[] args) {
    GenericMethodExample example = new GenericMethodExample();
    String[] strArray = {"Java", "Python"};
    example.<String>printArray(strArray);
}
```

但是 Java 官方表示，这样写太过繁琐，不如下面的：

```java
public static void main(String[] args) {
    GenericMethodExample example = new GenericMethodExample();
    String[] strArray = {"Java", "Python"};
    example.printArray(strArray);
}
```

在前面泛型的学习中，开发者应知道调用泛型应该去声明泛型类接受的参数化类型，不然编译器怎么知道呢？

这就需要讲述 Java 官方的类型推断了，下节专门讲述。

### 有界类型参数

#### 单个边界

有界类型参数其实已经出现了，即：

```java
// 泛型方法：返回两个值中的较大者（需实现 Comparable 接口）
public <T extends Comparable<T>> T max(T a, T b) {
    return (a.compareTo(b) > 0) ? a : b;
}
```

`<T extends Comparable<T>>` 为整个方法限定了其所接收的参数是有边界限制的，即 `T` 必须继承 `Comparable` ，`T` 继承了 `Comparable` 其中的方法，但是 `Comparable` 并不知道自己所接收的类型是什么类型，如果开发者不将 `Comparable` 泛型化，那么也就意味着在 `Comparable` 内部的方法还要进行类型的转化，有可能发生类型转换错误，所以为了避免这种错误，开发者可以直接让 `T` 去继承 `Comparable<T>`。

**边界的限定不仅局限于 `extends` ，对于 `implements` 等等也同样适用**

#### 多个边界

当开发者使用泛型且需要指定多个边界时，可以使用 `&` 符号完成链接，如下：

```java
<T extends B1 & B2 & B3>
```

**但在 Java 中类只能继承一个类，所以在 `<T extends B1 & B2 & B3>` 中，B1、B2、B3只能有一个类，其余为接口，且类优先写在第一个**

那如果都是接口呢？

**都是接口也只能用关键字 `extends` ，不能使用 `implements`** 。

## 泛型、继承、子类型

开发者知道 `Integer` 是 `Number` 的子类，假如现有泛型类型 `Box<Integer>` 、`Box<Number>`，那么是否可以认为 `Box<Number>` 是 `Box<Integer>` 的父类呢？

Java 官方明确告知了，**不可以**。
