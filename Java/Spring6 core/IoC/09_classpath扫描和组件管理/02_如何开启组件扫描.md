# 如何开启组件扫描

如何开启组件扫描拿出来单独讲，因为这也联系到前面的 XML 知识。

## 在 XML 中开启组件扫描

### `context` 命名空间

`context` 命名空间和 c 命名空间、p 命名空间一样，但不一样的是 context 命名空间是专门用来配置 Spring 注解配置，配置扫描等扩展功能的。

在最初的 Spring 的 XML 中只有 `<bean/>` ，但随着其功能的更新和迭代，Spring 需要专门的标签来进行 Spring 上下文功能扩展的配置。

对于前面学习的 `BeanFactoryPostProcessor` 中的外部文件的引入，开发者应该知道，如果想要进行外部文件的引入需要一个 `PropertySourcesPlaceholderConfigurer` 的 Bean。

知道了 `context` 命名空间就可以直接使用 `context` 命名空间引入 `PropertySourcesPlaceholderConfigurer` 。

```xml
<context:property-placeholder classpath="xxx.xxx"></context:property-placeholder>
```

### 常用的 `context` 命名空间

```xml
<!-- 引入注解配置 -->
<context:annotation-config></context:annotation-config>

<!-- 配置文件引入 -->
<context:property-placeholder location="外部文件路径"/></context:property-placeholder>

<!-- 开启组件扫描 -->
<!-- 如果开启了组件扫描，程序会隐式的实现<context:annotation-config> -->
<context:component-scan base-package="开发者所要扫描的包的路径（也可以是文件）"/></context:component-scan>

<!-- 等等，后面学到会讲述的 -->
```

### 总结

`context` 命名空间是 Spring 为了简化配置而设计的 “语法糖”，其底层通过自动注册 `BeanPostProcessor`、`BeanFactoryPostProcessor` 等核心处理器来实现功能。它并非直接 “适用于” 这些处理器，而是**通过封装这些处理器的注册过程，让开发者无需手动配置即可使用它们提供的功能**（如注解驱动、组件扫描、属性解析等）。

## 注解开启组件扫描

注解开启扫描就简单多了，如下：

```java
@Component
public class UserService {
    // 类的实现
}
```

直接再所要扫描的类上面使用 `@Component` 即可。

但这并不意味着 Spring 会在容器启动时自动扫描，开发者需要在启动类或者配置类中开启扫描，如下：

```java
@Configuration
@ComponentScan(basePackages = "org.example") // 或简写为 @ComponentScan("org.example")
public class AppConfig {}
```
