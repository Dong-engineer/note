# 集合的层次结构

在学习集合之前，先来了解下集合的整体层次结构，如下：

```plaintext
Iterable
└── Collection
    ├── List 【有序、可重复、支持下标】
    │   ├── ArrayList 数组实现，查询快增删慢
    │   ├── Vector 线程安全数组，效率低
    │   │   └── Stack 栈（继承Vector，过时）
    │   └── LinkedList 双向链表，增删快查询慢，同时实现Deque
    │
    ├── Set 【不可重复】
    │   ├── HashSet 哈希表，无序
    │   │   └── LinkedHashSet 哈希+双向链表，插入有序
    │   └── SortedSet 子接口（元素自然排序）
    │       └── TreeSet 红黑树，元素大小有序
    │
    └── Queue 【队列，先进先出】
        ├── Deque 双端队列子接口（可栈可队列）
        │   ├── ArrayDeque 数组双端队列，推荐栈/队列
        │   └── LinkedList 链表双端队列
        └── PriorityQueue 优先队列，堆结构，自动排序
```

 `Iterator` 接口，对于集合有一定了解的开发者不陌生，所有可迭代类均实现了该接口，而那些所有可迭代的类，均可以通过创建 `Iterator` 对象来实现内部元素的遍历、迭代。`Iterator` 是 `Collection、Map` 的父接口，这也说明了 `Collection、Map` 接口可以通过 `Iterator` 接口对象来进行内部元素的遍历。但是 `Iterator` 并不属于集合框架的一部分，也不仅仅只有集合框架才能通过 `Iterator` 接口来进行迭代。

集合框架整体分为两大部分，`Collection` => 集合，`Map` => 映射。

`Collection` 集合接口细分为 `List` => 列表，`Set` => 套装，列表和套装都是基于 `Collection` 来进行建模的。

`Map` 映射细分有 `HashMap、LinkedHashMap、TreeMap、ConcurrentHashMap` ，`Map` 映射存储元素的形式以键值对形式存储。

对于每一个类具体的差别，后面会详细讲述，无论是哪个细分类，都是基于 `Collection、Map` 两个接口来进行建模的，下节就详细讲述。
