# 抽象类

抽象着一概念想必开发者并不陌生，在数学中很多的概念都是抽象的，将很事物的特性抽象成一个集合体，并用以文字描述它，这就叫抽象。

抽象到最后都是要具体化的，抽象这一概念会帮助开发者大大缩减开难度。

在实际开发时，面向对象是编程范式，而面向抽象编程则是另一要领。这会大大降低代码的耦合度，方便后面对代码的维护。

对于*01_继承*一节中的向上转型（子类对象 -> 父类引用）就是面向抽象的一种实现，这大大降低了代码的耦合度，在实际很多细节很有可能考虑不到，于是开发者应当优先写好一个笼统的类（先假设是一个父类），后面根据不同情况通过继承实现不同的具体细节（实际开发中通常使用接口，这里做例子）。

但是在创建对象的时候通常本类的引用`new`本类对象，这种做法可以但代码的耦合度很强，一般地不去细想，开发者可能认为本类的引用只能`new`本类对象，但学过继承后，还可以`new`其子类对象，这种做法就会降低代码的耦合度，因为开发者很可能只知道某个需求需要使用父类引用，但是并不知道其实现的具体细节（即不知道后期需要去`new`什么对象），所以 Java 就倡导开发者使用向上转型。

向上转型大大降低了代码耦合度，但是在父类的方法实现中也是笼统的写了其方法体，这也就说明父类也存在一定的耦合度。

那该怎样做才能消除耦合度呢？

Java 提供了抽象类，在某一类的方法中还是实现了一些具体代码，那么干脆直接不写方法体，只声明方法名和其一些修饰。

## abstract

使用`abstract`关键字声明抽象类和抽象方法。

`public` 、`abstract` 关键字可以省略。

```java
// 抽象类
public abstract class GraphicObject {
    // 抽象方法
    public abstract void draw();
    
	abstract void draw();
    
    // 简化写法
    void draw();
}
```

## 抽象类与接口的比较

抽象类无法被实例化。并且它们可能包含声明的多种方法但是，使用抽象类，您可以声明非 static 和 final 的字段

抽象类可以被多个类继承，但是接口只能被一个类实现。且当某一子类实现抽象类的时候，其抽象方法是必须在子类中也要实现的。

### 何时选择抽象类？

- 当你需要在多个相关类中共享代码或状态时。
- 当你需要使用 `protected` 或 `private` 成员时。
- 当你需要存储对象的动态状态（非静态字段）时。
- 当你需要定义非 `final` 的方法（允许子类重写）时。

### 抽象类实现接口

当一个抽象类实现了某一接口的时候，根据接口的规则，抽象类是一定要实现接口中的所有方法的。但是当抽象类具体的实现某一方法这也就意味着该方法不再是 `abstract` 。

于是 Java 规定了在抽象类中无需实现接口中的方法（无需声明），但是继承了抽象类的子类必须实现其抽象父类实现的接口方法。
