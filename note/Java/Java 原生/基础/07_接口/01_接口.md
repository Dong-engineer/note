# 接口

在 Java 官方文档中是这样介绍的。

在软件工程中，在许多情况下，不同的程序员群体必须同意一个 “合同” 来阐明他们的软件如何交互。

例如，想象一个未来社会，计算机控制的机器人汽车在没有人工作员的情况下运送乘客穿过城市街道。汽车制造商编写了作汽车的软件（当然是 Java），例如停止、启动、加速、左转等。另一个工业集团是电子导引仪制造商，他们制造的计算机系统接收 GPS（全球定位系统）位置数据和无线传输交通状况，并使用这些信息来驾驶汽车。

汽车制造商必须发布一个行业标准接口，详细说明可以调用哪些方法来使汽车移动（任何汽车，来自任何制造商）。然后，指南制造商可以编写软件，调用界面中描述的方法来命令汽车。任何一个工业集团都不需要知道另一个集团的软件是如何实现的。事实上，每个集团都认为其软件具有高度专有性，并保留随时修改它的权利，只要它继续遵守已发布的界面。

在 Java 编程语言中，*接口*是一种引用类型，类似于类，它*只能*包含常量、方法签名、默认方法、静态方法（私有或公共、不受保护）、实例非抽象方法（私有、非公共、不受保护）和嵌套类型。方法主体仅存在于默认方法、私有方法和静态方法中。接口无法实例化——它们只能由类实现或由其他接口扩展。

## 接口的声明

接口是一种特殊的类，和 `record` 的声明类似，接口是通过 `interface` 来声明接口的。

```java
public interface MyInterface {
}
```

在上文中提到了接口只能包含包含常量、方法签名、默认方法、静态方法（私有或公共、不受保护）、实例非抽象方法（私有、非公共、不受保护）和嵌套类型。下面一一举例。

### 1. **方法签名（Method Signature）**

方法签名是方法的唯一标识，由**方法名**和**参数列表**（参数类型、顺序、数量）组成，**不包括返回类型**和**访问修饰符**。

**示例**：

```java
interface MyInterface {
    void method1(int a, String b);  // 方法签名: method1(int, String)
    int method2(double x);          // 方法签名: method2(double)
}
```

**特点**：

- 接口中的方法默认是`public abstract`，无需显式声明。
- 实现类必须提供方法的具体实现，且签名必须完全匹配。

### 2. **常量（Constants）**

接口中定义的字段默认是`public static final`常量，必须在声明时初始化，且不能被修改。

**示例**：

```java
interface MyInterface {
    int MAX_VALUE = 100;           // 等价于 public static final int MAX_VALUE = 100;
    String DEFAULT_NAME = "Guest"; // 常量名通常大写，用下划线分隔单词
}
```

**使用**：

```java
int value = MyInterface.MAX_VALUE; // 通过接口名直接访问常量
```

### 3. **默认方法（Default Methods）**

Java 8 引入的特性，允许接口中包含方法体，使用`default`关键字修饰。

**示例**：

```java
interface MyInterface {
    default void printInfo() {     // 默认方法
        System.out.println("这是默认实现");
    }
}
```

**特点**：

- 默认方法可以被实现类继承或重写。
- 解决了接口升级时需要修改所有实现类的问题（如 Java 集合框架的改进）。

### 4. **静态方法（Static Methods）**

接口中可以定义静态方法，使用`static`关键字修饰，必须有方法体。

**示例**：

```java
interface MyInterface {
    static void showMessage() {    // 静态方法
        System.out.println("接口静态方法");
    }
}
```

**使用**：

```java
MyInterface.showMessage(); // 直接通过接口名调用，无需实例化
```

### 5. **私有方法（Private Methods）**

Java 9 引入的特性，允许接口中定义私有方法，只能在接口内部被默认方法或静态方法调用。

**示例**：

```java
interface MyInterface {
    default void publicMethod() {
        privateHelper();           // 调用私有方法
    }
    
    private void privateHelper() { // 私有方法
        System.out.println("私有辅助方法");
    }
}
```

**特点**：

- 私有方法不能被实现类访问或重写。
- 用于抽取接口内部的重复逻辑。

### 6. **嵌套类型（Nested Types）**

接口中可以定义嵌套的类、接口或枚举，默认是`public static`。

**示例**：

```java
interface MyInterface {
    enum Status {                  // 嵌套枚举
        ACTIVE, INACTIVE
    }
    
    class Helper {                 // 嵌套类
        public static void assist() {
            System.out.println("辅助方法");
        }
    }
}
```

**使用**：

```java
MyInterface.Status status = MyInterface.Status.ACTIVE;
MyInterface.Helper.assist();
```

## API

API（应用程序编程接口），在实际开发中，大部份公司是以业务为主进行开发，有些公司会提前封装好这些业务逻辑为其他公司提供 API ，这大大缩减了程序开发的周期。Java 和 一些标杆企业、计算机的领军人物制定了一些开发时接口编写的准则（后面会学习到的）。开发者应当按照这些标准对业务需求进行开发以便于后期的维护。而这些在开发中所使用的其他公司的接口叫做 *第三方API*。

## 接口 vs 抽象类

接口的设计目的是定义**行为契约**，而不是实现细节。相比抽象类：

- **接口**：只能包含常量和方法定义，支持多重实现（一个类可实现多个接口）。
- **抽象类**：可以包含实例字段、构造方法和具体方法，单继承（一个类只能继承一个抽象类）。

## 后语

在实际开发中，开发者无需关心第三方API是如何实现的。当然你也可以自己写你自己的API。

Java 学习到了这里，还差一些东西就可以完全结束 Java 基础的学习了，在实际开发中使用第三方API很常见，想要做自己的API很难，无论是硬件、还是软件都要有一定硬性要求，API需要开发者用心思考其怎样编写才能达到其最佳效果，这些API的编程并不难（都是通过基础语法实现的），但需要不断的思考探索去优化开发者自己的作品。
