# 类型擦除

在使用泛型进行类型转换机制的时候，前面讲述了，无需再去对其使用强制类型转化，那这是为什么？

是不是在使用泛型的时候，底层对其创建了一个新类型的对象呢？

下面会进行讲述。

## 类型擦除机制

在使用泛型进行类型转换机制时，不是在运行时创建了新类型的对象，而是 Java 的类型擦除机制。

**在编译后，在类型擦除过程中，Java 编译器会擦除所有类型参数，如果类型参数有界，则用其第一个 bound（如果类型参数有界，即extends后的第一个类、或接口）或 `Object`（如果类型参数无界）替换每个参数。**

### 类型参数无界

如下：

```java
public class Node<T> {

    private T data;
    private Node<T> next;

    public Node(T data, Node<T> next) {
        this.data = data;
        this.next = next;
    }

    public T getData() { return data; }
    // ...
}
```

 Java 编译器会将`T`替换为 `Object`：

```java
public class Node {

    private Object data;
    private Node next;
    
    public Node(Object data, Node next) {
        this.data = data;
        this.next = next;
    }
    
    public Object getData() { return data; }
    // ...

}
```

### 类型参数有界

如下：

```java
public class Node<T extends Comparable<T>> {

    private T data;
    private Node<T> next;

    public Node(T data, Node<T> next) {
        this.data = data;
        this.next = next;
    }

    public T getData() { return data; }
    // ...
}
```

Java 编译器将有界类型参数 `T` 替换为第一个绑定类 `Comparable` ：

```java
public class Node {

    private Comparable data;
    private Node next;

    public Node(Comparable data, Node next) {
        this.data = data;
        this.next = next;
    }

    public Comparable getData() { return data; }
    // ...
}
```

### 类型转换

对于类型转换，其实前面就已经讲述过，Java 为了避免在运行时发生类型转换错误，**于是便在编译时会对代码上下文进行类型推断，从而隐式进行类型转换。**

如下：

```java
// 编译前：
String s = stringList.get(0);

// 编译后（等效代码）：
String s = (String) stringList.get(0);  // 编译器自动插入强制转换
```

## 擦除泛型方法

擦除泛型方法和类型的擦除机制一样。

### 类型参数无界

```java
public static <T> int count(T[] anArray, T elem) {
    int cnt = 0;
    for (T e : anArray)
        if (e.equals(elem))
            ++cnt;
        return cnt;
}
```

编译后：

```java
public static int count(Object[] anArray, Object elem) {
    int cnt = 0;
    for (Object e : anArray)
        if (e.equals(elem))
            ++cnt;
        return cnt;
}
```

### 类型参数有界

假设有以下类：

```java
class Shape { /* ... */ }
class Circle extends Shape { /* ... */ }
class Rectangle extends Shape { /* ... */ }
```

```java
public static <T extends Rectangle> void draw(T shape) { /* ... */ }
```

编译后：

```java
public static void draw(Rectangle shape) { /* ... */ }
```

## 桥接方法

有很多的时候类型擦除机制会导致开发者预想不到的异常，如下：

```java
public class Node<T> {

    public T data;

    public Node(T data) { this.data = data; }

    public void setData(T data) {
        System.out.println("Node.setData");
        this.data = data;
    }
}

public class MyNode extends Node<Integer> {
    public MyNode(Integer data) { super(data); }

    public void setData(Integer data) {
        System.out.println("MyNode.setData");
        super.setData(data);
    }
}
```

通过以上代码，可以看出 `MyNode` 继承的是 `Node<Integer>` 泛型类型。

下面做测试：

```java
MyNode mn = new MyNode(5);
Node n = mn;            // 使用了原始类型(raw type) 警告
n.setData("Hello");     // 类型转化错误
```

上面代码是可以运行的，但是会报类型转化错误。

类型擦除后，代码如下：

```java
MyNode mn = new MyNode(5);
Node n = (MyNode)mn;
n.setData("Hello");
```

那么从头开始分析：

对于 `Node<T>` 和 `MyNode` 两个类，类型擦除后的代码，如下：

```java
// T 是无界的，故转化为 Object
public class Node {

    public Object data;

    public Node(Object data) { this.data = data; }

    public void setData(Object data) {
        System.out.println("Node.setData");
        this.data = data;
    }
}

// MyNode继承的是Node<Integer>
public class MyNode extends Node {

    public MyNode(Integer data) { super(data); }

    public void setData(Integer data) {
        System.out.println("MyNode.setData");
        super.setData(data);
    }
}
```

在 `MyNode` 和 `Node` 中均有名为 `setData()` 的方法，而 `MyNode` 继承了 `Node` ，那么在 `MyNode` 中这不就是重写了 `setData()` 方法，显然这是错误的说法，重写的前提条件就是无论是方法名还是参数列表都是一样的，但是在 `MyNode` 中很明显参数列表不一样，所以这是重载了 `setData()` 。

所以这也就是为什么，父类引用 `Node n` 指向子类对象 `MyNode mn = new MyNode(5)` ，但在调用 `setData()` 方法时并未覆盖父类方法的原因。

Java 为了解决这个问题，提出了桥接方法，即然无法在运行时去调用子类的方法，那么干脆直接在编译时，原封不动的将 `setData(Object data)` 复制到 `MyNode` 里面，那方法体怎书写呢？既然是重载 `setData()` 方法，那直接在 `setData(Object data)` 去调用重载的方法，但是需要对参数 `Object data` 进行转换，这很简单，因为 `Object` 特性的缘故，可以很轻松避免类型转化的问题。

代码如下：

```java
class MyNode extends Node {

    // 桥接方法，在编译时编译器自动添加
    public void setData(Object data) {
        setData((Integer) data);
    }

    public void setData(Integer data) {
        System.out.println("MyNode.setData");
        super.setData(data);
    }

    // ...
}
```

通过桥接方法简洁的去调用 `MyNode` 中原始的 `setData()` 。以达到方法重写的目的。

同时，这也是

```java
MyNode mn = new MyNode(5);
Node n = mn;            // 使用了原始类型(raw type) 警告
n.setData("Hello");     // 类型转化错误
```

这也是该代码会报 `ClassCastException` 的根本原因。
